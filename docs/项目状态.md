# 项目状态

更新日期：2026-10-25。

这是链路验证版本，不是可直接生产的设计。生成器当前只支持5V LED和RC低通两个固定模板，不支持ESP32-S3整板自动生成。

## 已有证据

- 本机独立目录BASE-01候选：本地测试27/27、上游121/121、双模板生成和格式校验6步通过。
- 两模板已通过LCEDA Pro 4.1.71客户端回读并保存截图。解析成功不等于电气验收。
- 必要生成源码、BOM参数、测试和复现脚本纳入本次同步；原始客户资料、私有计划、实验SDK和构建缓存不公开。

## 尚未完成

- 第三方干净环境验收和Docker实际构建/运行尚无证据。Docker只覆盖六步基础复现，已审阅输入范围。
- 原模板电气审计仍有ATTRMATCHCODE及PCB网表不一致。RC临时副本官方同步实验可消除Netlist Error，但未推广到生成器。
- 客户端保存工程的DOCHEAD额外ticket字段触发原版上游校验器异常。隔离补丁通过10项回归及121项smoke，尚未接入vendor；[上游Issue #2](https://github.com/easyeda/easyeda-eprj3-skill/issues/2)及[中文说明](https://github.com/easyeda/easyeda-eprj3-skill/issues/2#issuecomment-6396044559)已发布。
- ESP32-S3实板实验曾通过受限bootloader进入一次原芯片识别探针；后续启动复现不稳定，尚未验证Flash稳定性、BME280通信或温湿度功能。该实验不属于本次生成器基线，不构成正式修复。
- 参考设计入库、A/B实际对照、目标整板同源pinmap/netlist、制造文件及实物闭环尚未验收。

## 使用与验收

从本仓库同步版本运行 `npm test` 和 `node scripts/reproduce.js`，保存当前commit、系统/Node版本、完整命令和原始日志。桌面客户端检查单独记录。每项以实际证据判断，不将未运行检查写成通过。

详细基线证据口径见 [验证记录](verification.md) 和 [复现指南](复现指南.md)。本地原始证据保留，不随本次Git同步上传；公开报告仅说明已验证范围与缺口。

本次同步前已对拟提交内容的独立目录实际复验：本地27/27、上游121/121、基础复现6/6和双模板真实客户端回读通过。结果详见验证记录；未纳入的本地实验文件不作为运行依赖。
