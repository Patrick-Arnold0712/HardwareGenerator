## 能做什么

1. 保留原话，明确选择S3+BME280、USB-C5V和串口目标。
2. 对照固定Adafruit Feather ESP32-S3 8MB No PSRAM参考来源；OLED、N16R8、改板、VDD5V直供和必须保证精度等冲突会阻断。
3. 接受**整块参考原样**后，审核只表示资料方向可对照。电池管理、NeoPixel等附加电路仍然保留；没有声称只剩两颗芯片。
4. 只有真实资产已归档复核、其大小与SHA256匹配，才载入真实原理图/PCB，并提供参考工程下载。缺文件或错hash不显示旧图。
5. 项目ID、需求revision/指纹、参考版本、图/工程hash绑定；改需求即清旧审核/图/工程入口，再确认再审核。

## 尚不能做什么

- 不改电路/引脚/尺寸/布线；不自动写固件、仿真、烧录或制造。
- 不证明温湿度测量精度、串口程序、供电完整性或整板可靠性。
- 图片和可编辑工程即便导入/打开，也不等于ERC/DRC/网表或生产通过。旧开发板实验不自动属于这块参考。
- 未接实时数据库、付费LLM；输入在当前浏览器，不自动保存。网页静态文件仍由本地服务提供。

## 本地运行

在仓库根目录：

```powershell
python -m http.server 7803 --bind 127.0.0.1 --directory web-demo-boardflow-r1
```

浏览器打开 `http://127.0.0.1:7803/`。需要HTTP而非直接双击index.html，因为快照与资产用同源fetch读回并校验哈希。

选择温湿度、室内/查看、USB-C5V、串口、周围空气温度、S3+BME、8MB无PSRAM、整块参考原样、目标0～50℃/±0.5℃、误差仅为待验证目标，再明确确认。所有字段初始为空，不默认替用户接受参考。

## 文件与执行位置

- requirements-core.js / condition-engine.js / condition-snapshot.js：旧r2原字节副本，沿用有边界的需求与温度条件规则，未改旧文件。
- boardflow-core.js：参考方向门控、版本/指纹绑定、资产完整性检查与需求失效。
- reference-snapshot.json：新固定最小参考快照，不是旧9记录，也不是实时13源离线库查询。
- reference-lock.js：该快照准确字节SHA256和版本；更新真实资产后必须另行核对并重验，不把局部改动冒充旧hash。
- app.js：真实调用上述核心、fetch同源固定文件；只在文件检查通过后建Blob图和下载链接。不存在服务器自动绘制或布线。
- assets/（真实资产交付后）：图和工程原字节副本；来源/衍生变化/工具/限制写入快照。

记录结果与“工程合格”分开：资料方向一致仍`requirements_fulfilled=false`、`design_approved=false`。工程范围见快照`verification`，未执行保持`NOT_RUN`。
